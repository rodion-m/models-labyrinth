## Evidence and interpretation

The IDs below are catalog snapshot identifiers, not necessarily benchmark names. The database observations are sourced from BenchLM; the URLs in the last column are the canonical paper, project, code, or data sources I found. A suffix such as `Python`, `WithTools`, `NoTools`, `ForceAnswer`, `Avg`, or `Lite` is retained exactly and treated as a possible evaluation condition rather than silently merged into the base dataset. “Not published” means that the primary artifact does not specify the condition; it is not an assumption that no tools were used.

Scores are only comparable when dataset revision, prompt/parser, sampling, tools, judge, and scaffold match. “Higher” means higher is better; WER/edit distance/error directions are marked “lower.”

## Adjacent priorities not represented by a matching snapshot ID

### OSWorld and computer use

There is no `multimodalGrounded.osworld` or `multilingual.osworld` ID in the current 67-ID inventory. OSWorld is still the correct adjacent reference for end-to-end computer use: real web/desktop applications, file I/O and multi-application workflows in a configured OS, with execution-based task evaluators. The original release contains 369 tasks; OSWorld-V2 adds a separately pinned 108-workflow long-horizon release (`osworld-v2-2026.06.24`) with versioned task files, assets and mocked websites. ScreenSpot-Pro measures element grounding only, and Vision2Web measures website development; neither should be reported as OSWorld task success.

Primary references: [OSWorld paper](https://arxiv.org/abs/2404.07972), [OSWorld repo](https://github.com/xlang-ai/OSWorld), [OSWorld-V2 repo](https://github.com/xlang-ai/OSWorld-V2).

### Million-context document evaluations

No matching row is a benchmark whose individual input is a million tokens. MMLongBench-Doc uses roughly 20K tokens per document on average; OfficeQA Pro uses a very large multi-document corpus (about 89K pages and 26M numerical values), and GDP.pdf/OmniDocBench/OCRBench V2 stress professional PDF perception and extraction. A model’s 1M-token context-window setting is an execution condition, not proof that the benchmark itself is a million-token test. For a million-context workload report, record the document packing, page/image tokenization, retrieval/oracle access, context position, truncation, and judge separately.

## Source provenance and reproducibility checklist

For every score copied from `models_db.json`, preserve the BenchLM observation URL and source timestamp alongside the canonical benchmark URL. Before comparing rows, pin: benchmark commit or dataset revision; split; image/PDF/video/audio preprocessing; prompt and answer parser; temperature/repeats; frame rate/subtitles; Python/browser/document tools and budgets; model context limit; judge model/version; and execution container. This is especially important for aliases (`aa*`, `liquid*`), continuous arenas, and tool/Python variants, which are not canonical benchmark releases merely because their names contain a familiar benchmark token.
